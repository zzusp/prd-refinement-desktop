# 启动时 Runtime 与版本检查

## 目标

- 应用启动后，在 Runtime 已安装且认证状态正常时自动执行一次真实模型连接检测。
- 应用启动后立即检查一次正式 GitHub Release，并在运行期间每 1 小时复查。
- 自动检查不能阻塞任务列表回读，不自动下载或安装更新，现有手动检查入口继续可用。

## 现状

启动流程仅调用 `inspectRuntime` 读取安装、版本和认证状态，因此顶部栏最多显示“已安装”，无法证明模型路由可用。应用版本检查只在 Runtime 配置页点击“检查更新”后执行。

## 方案

1. 将 Runtime 启动检查拆为“基础状态检查 → 条件满足时读取已保存配置 → `testRuntime` 真实连接检测”。未安装、未认证或基础检查异常时不发起模型请求。
2. Runtime 检测与任务列表、归档任务回读并行，连接检测失败时保留基础状态并显示可重试原因。
3. 版本检查在应用级状态中执行，启动立即检查，此后以 1 小时间隔复查；同一调度器内前一轮未完成时跳过重复触发。
4. 自动与手动版本检查共用 `checkAppUpdate` IPC 和应用级结果，顶部栏在发现新版时显示版本提示，配置页继续提供手动重试和正式发布页入口。

## 验证

- 单元测试覆盖 Runtime 正常、未安装、未认证、连接异常，以及版本启动检查、1 小时复查、停止清理。
- 执行全量测试、类型检查、生产构建、UI 契约检查和严格静态审计。
- 打包并启动真实 Windows Electron 应用，读取顶部 Runtime 已连接状态及配置页自动版本检查结果。
