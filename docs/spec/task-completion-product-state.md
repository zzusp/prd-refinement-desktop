# 任务完成状态收敛

## 用户纠正

“平台未完成”仍把内部交付校验暴露成用户任务状态，与产品只输出功能模块和需求清单的边界冲突。任务状态应回答执行是否结束；产物状态应回答当前文件是草稿还是正式包，两者不能互相派生。

## 收敛方案

1. 七个阶段成功执行结束后，任务统一为 `completed/100`。
2. 历史 `needs-attention` 且全部阶段已完成的任务在加载时规范化为 `completed/100`，清除旧平台提示。
3. 只有真实执行失败使用 `failed`，并显示错误和恢复操作。
4. `delivery.state` 和 artifact kind 继续独立区分草稿与正式包，不因任务 completed 放宽准入。
5. 用户界面不再出现“平台未完成”“正式结果需要重新处理”或由内部校验产生的处理入口。

## 验证

- 单元测试覆盖历史任务规范化和结果页文案。
- 真实任务副本显示“已完成 · 100%”，同时仍保留 blocked/draft 产物属性。
- 导出路由测试继续证明 blocked 结果进入 drafts，ready 结果进入 deliveries。
