# 细化输出证据契约修复

日期：2026-09-14。状态：待实施方案。本次只制定修复与验收方法。

## 1. 目标及已确认根因

目标：模型输出的需求内容与证据不再依靠两套数组的下标关联；错误在模型输出边界被明确识别，合法内容经过确定性转换后进入既有领域校验。保留严格来源校验，错误不能被自动补证据、删条件或跳过批次掩盖。

已确认任务 `T-8CACEBFC` 在 `details-F-003-batch2` 两轮执行共四次响应失败：行为证据为空、遗漏 state、一个条件没有绑定组、条件证据输出为字符串而非数组。最后一次同时存在五条限制对应十一个平铺证据编号。

诊断保存在该任务用户数据目录的 diagnostics 下。原始响应含业务资料，不复制到公开仓库；回归夹具使用脱敏合成数据保留同样的错误结构。

关键实现：

- `electron/scheduler-v2.ts:39`：模型示例的条件及绑定均为空数组，只用文字说明数量对应。
- `electron/source-evidence.ts:83`：非数组的证据组原样穿透转换层。
- `electron/domain.ts:241`：最终由内部 SourceRef 校验报出 sourceUnitIds 错误。
- `electron/scheduler-v2.ts:736`：一次只返回首个校验错误，至多一次纠错，并重新生成完整节点结果。

这些是输出契约及错误恢复问题，不是用户缺少任务参数。当前校验已阻止错误结果进入任务。

## 2. 路径取舍

| 路径 | 结论 | 理由 |
| --- | --- | --- |
| 只增加提示示例、重试次数或切换更强模型 | 不采用为主要修复 | 无法消除内容与证据两套数组需要对齐的问题；本任务已有反复纠错失败证据 |
| 保留平行数组，增加完整结构校验 | 可改善报错，但不作为最终结构 | 能阻止错误穿透，仍要求模型维护数组层级及数量；结构正确也可能按错下标关联 |
| 内容和证据成对输出，程序编译为现有领域对象 | 采用 | 从结构上移除条件与证据的平行数组，缩小模型负责的内容，并复用已有持久化和导出契约 |

不自动把平铺证据数组包一层，也不平均分配证据。五条限制与十一个证据如何对应需要按原文判断，程序不能猜测。

## 3. 唯一的模型输出结构

示例中的 E1、E2、E3 仅表示必须从本次 evidenceCatalog 选择的编号：

```json
{
  "requirements": [{
    "id": "LOCAL-R1",
    "title": "提交申请",
    "behavior": {"text": "用户可以提交申请", "evidenceIds": ["E1"]},
    "conditions": [
      {"text": "用户已登录", "evidenceIds": ["E2"]}
    ],
    "constraints": [
      {"text": "无权限时禁止提交", "evidenceIds": ["E2", "E3"]}
    ],
    "explicitAcceptanceEvidenceIds": []
  }],
  "clarifications": []
}
```

- behavior 必须有非空 text 和非空 evidenceIds。
- conditions、constraints 是对象数组，可为空；每个对象都必须有非空 text 和非空 evidenceIds。多项内容分别形成对象，同一证据可以支持多个对象。
- explicitAcceptanceEvidenceIds 保留现有含义，程序取回原文明示验收条件及其证据；没有明示条件时为 []。
- 模型不再输出 evidenceBindings、sourceUnitIds、state、字符偏移或抄写原文 quote。来源由选择的证据派生；接收的新候选状态由程序设为 draft，并交由既有审查流程推进。
- id、title 仍由模型提供并检查唯一性及节点权限；有据修正须保留正式需求 ID，不能借格式修正新增或删除需求。
- Clarification 继续使用现有独立契约，保留原有业务澄清规则；不得把输出格式错误转成业务问题。

内部 RequirementDetail 仍保存字符串 behavior、字符串数组 conditions/constraints 和 SourceRef 形式的 evidenceBindings。新增行为只发生在模型输入输出边界，不要求改动 Excel、CSV 或结果页面。

## 4. 一条接收路径

JSON 解析 → 节点模型输出校验 → 证据解析和领域对象编译 → 既有领域、来源及关系校验 → 保存批次结果。

在现有 source-evidence.ts 中复用证据解析器，为需求输出提供专门的校验/编译入口；避免将新旧两种需求格式放入通用递归函数中猜测。scheduler 中明确按节点选择接收函数。普通候选、关系与澄清继续使用其已有入口。

模型结构校验一次收集可独立判断的问题：必填字段、类型、空文本、空证据、重复 ID、额外禁止字段和未知证据。父级结构不合法时停止检查该子树，避免制造后续无意义错误。

错误包含 code、path、expected 和 actual 类型/数量；实际业务文本不整段显示在页面。示例：

```text
requirements[0].conditions[0]：需要 {text, evidenceIds} 对象，实际为字符串。
requirements[0].constraints[2].evidenceIds：证据编号数组不能为空。
requirements[1].behavior.evidenceIds[0]：证据 E99 不在本批提供的目录中。
```

编号存在不等于证据支持内容。编译器只确认合法引用、位置与结构；业务忠实性继续由现有依据核查及复核负责。

领域层同步检查非空行为证据、每个实际条件/限制的非空证据组、组数匹配及有效来源范围，防止其他内部调用绕过模型入口。不得静默丢弃多余证据组。

## 5. 有界纠错与诊断

保留一次初始调用加一次纠错，不增加盲目重试。初次失败时保存完整本地响应和结构化问题列表；纠错反馈包含所有可定位的结构错误、固定的非空示例和原始节点请求。

原始请求已经含冻结原文和证据目录，纠错只允许使用该目录。继续返回完整节点 JSON，不引入 JSON Patch 协议或新的局部编辑服务；通过校验后仍须执行现有依据核查，不能声称完整重生成一定不改变业务语义。

反馈在完整请求预算内发送：按条数与大小限定反馈展示并明确还有多少问题，完整诊断仍保存本地；预算仍不足时报告具体请求超预算，不截断原文或需求后继续。格式错误、引用错误与 Runtime/网络错误继续分别归类。

两次均失败时保存失败，不提交该批半成品。页面摘要说明具体需求和字段、两次失败类别及存在完整诊断；保持现有纯文本错误入口，不新增页面设计。

修复降低结构不一致概率并提升诊断能力，不保证模型永远正确或任务永不失败。

## 6. 同因调用点和恢复范围

需同步更新首次逐功能细化、共用 detailSchema 的有据修正，以及相应的模拟 Runtime 响应。修正节点输入的 currentRequirements 也投影为模型可理解的成对结构，避免提示要求新格式、输入却示范旧格式。

投影中仅使用当前允许证据目录可表达的字段；无法以完整句段精确表达已有选区时应明确定位该项，不能用相交即匹配扩大依据。既有 patch 所有权、修正影响范围和提交前复核保持有效。

本方案不增加分片检查点：当前 detailResults 按功能持久化，一个功能内部分批次失败，续作会重做该功能未保存的批次，而非保证只重跑 batch2。不能把改变输出结构与新增调度恢复机制混为一项修复。

输出协议发生变化，按项目规则升级 pipeline 版本。旧失败任务保持可查，用原任务保存的原材料和用户说明创建新任务，不混用旧检查点续跑。应先核对 restart 是否保留这些输入身份、清空旧中间结果，再恢复此次真实任务。不会仅修改旧记录中的 pipelineVersion 来强行续跑。

## 8. 验收门槛

实施后在 docs/acceptance/detail-evidence-contract-repair/ 记录 matrix.csv 及逐轮证据；全部约定用例通过后再写报告。

1. 合法成对字段可编译成当前 RequirementDetail，文本、位置和多证据绑定保持一致。
2. 脱敏重现本任务四种错误：空行为证据、旧格式遗漏字段、无条件证据组、平铺证据；错误定位到模型字段，不能再漏到内部 sourceUnitIds 兜底报错。
3. 一份响应同时包含多个独立错误，首次反馈能列出全部预算内可判定问题；纠错成功后只提交完整合法结果。
4. 假证据、其他批次证据、空组、多余组和伪造 SourceRef 均被拒绝；检查同一来源不能充当自动兜底依据。
5. 有据修正复用新契约，保留正式 ID、未涉及内容、范围和审查约束，不因转换扩大证据选区。
6. 两次格式失败、Runtime 故障、纠错预算不足均保存准确失败状态，无半成品提交、无伪造业务澄清。
7. 原任务重新开始后使用同一材料和说明，旧检查点不混入；新任务和原失败记录独立。
8. 相关测试、全量测试、typecheck 和 build 通过；实际桌面实例加载修复版本，再从原输入建立新任务验证 F-003 全部细化批次和后续分析流程。

真实任务通过只能证明该次流程成功。仍须核对条件、限制和证据对应，避免通过删除条款或把五条限制合并成一句来迎合校验。
