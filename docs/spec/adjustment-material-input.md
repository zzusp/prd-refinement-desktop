# 调整结果时更新 PRD 与补充资料

日期：2026-09-16。状态：实施中。

## 目标

完成任务的“调整结果”支持两条明确路径：

1. 仅调整模块组织或需求颗粒度时，继续提交调整说明并局部生成新版本。
2. 主 PRD 或补充资料发生变化时，从当前结果冻结的资料复制独立草稿，允许更换主 PRD、添加或移除补充资料，再完整分析并发布同一任务族的新版本。

旧结果、旧输入快照和产物不被覆盖；补充资料不能通过调整说明伪装成主 PRD 事实。

## 复用与边界

- 复用 `MaterialWorkspace` 的文件选择、目录添加、角色调整、索引和错误恢复，不新建第二套上传组件。
- 复用 `MaterialBundleStore`，由主进程从任务冻结快照创建调整草稿；渲染进程不能传入任意本地路径作为旧输入。
- 新资料路径执行完整七阶段分析，不复用旧模型候选或检查点；结果成功后分配基准版本的下一版本号。
- 提交前和发布时都校验基准版本仍为最新，防止并发调整覆盖更新结果。
- 首版每个基准版本只复用一个未提交的资料调整草稿；不实现跨轮增量重算或语义差异报告。

## 验证

- 资料克隆保持主 PRD、补充资料、逻辑路径和文件内容；更新页默认展示主 PRD、按逻辑路径分组的补充文件与资料目录、当前提示词，并展开文件明细供用户直接调整。原资料包删除后仍可从任务冻结快照创建草稿。
- 对尚未保存 `materialSnapshot`、但仍保留冻结输入目录和来源文档身份的旧任务，从这两项冻结数据恢复资料；已经创建的空调整草稿就地补齐，不回读可能变化的原始上传路径，也不覆盖用户已添加的资料。
- 新资料分析属于原任务族，发布为下一结果版本；陈旧基准版本拒绝提交或发布。
- 调整面板同时展示“更新资料并重新分析”和“按说明调整”，两者含义、按钮层级和错误恢复清楚。
- 类型检查、单元测试、生产构建、UI 契约、严格 UI 审计和真实 Electron 操作通过。
