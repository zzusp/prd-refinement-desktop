# 仅输出功能模块与需求清单

日期：2026-09-14。实施前方案，依据用户明确选择“只输出功能模块和需求清单”，覆盖此前保留待处理事项和建议的产品边界。

## 现状与目标

当前 model-output-schemas.ts、domain.ts 强制问题包含背景、影响、级别理由，阻塞项还需建议。scheduler-v2.ts 将该契约送入细化、核查及修正。页面和导出继续消费这些内容，单改文案不能消除模型分析负担。

新产物仅为 PRD 原文支持的模块和简短需求项及其出处。不生成问题、建议、默认口径、业务阻塞分析、独立主张/条件栏目。原文明示的必要条件和否定仍需体现在条目语义中；无法从 PRD 得出的规则不补写。

## 实施范围

1. 保留原七阶段顺序。细化仅生成 requirements；依据核查和修正只检查已有清单是否忠于 PRD，不生成业务问题或建议。平台执行和引用校验错误仍按错误处理。
2. 从可达模型 Input/Proposal/Result 去除问题/建议生成结构，确定性校验拒绝越界字段；升级 Pipeline，禁止复用旧回执。局部组织调整继续有效，用户新增业务规则不能越过 PRD 红线。
3. 删除建议生成/采纳的调用入口和页面操作，结果只显示模块与需求、原文入口及调整说明。保留任务错误诊断，不能把平台失败隐藏。
4. CSV、Excel 和 requirements.json 只导出清单和来源，移除 pending.json、问题/建议工作表及相关使用说明。原始 PRD 与资料继续随包交付。
5. 历史文件不迁移或删除；新任务及新产物遵循新契约，不建立旧协议兼容运行路径。历史问题类型如仍用于读取旧数据，不允许通过新生成链写入。

## 分工与验证

主代理负责调度、局部调整、版本、集成和文档；子代理分别负责契约/领域、页面、导出。文件互斥编辑，先读源码再改。

验证：禁止新增问题/建议的契约反例、需求关键限定保留、无原文依据不新增、原七阶段和失败重试、调整重跑、包文件与工作表回读；执行全量测试、typecheck、build、UI 静态门禁及真实 Electron 页面检查。真实模型验证与受控测试分别记录，旧结果不冒充本轮通过。
