# 结果工作台显示修正

日期：2026-09-14。针对执行记录、全部需求、批量选择表格和运行统计区的当前问题实施。

## 目标

1. 将“平台检查记录”改为执行记录中的折叠“清单校验明细”，说明它只记录平台生成清单与原文不一致的修正过程，不形成用户待办。
2. 新旧任务都能打开全部需求。旧任务只读字段通过统一展示函数转换为短标题和原文引用，不迁移持久数据。
3. 功能与需求、全部需求的表头和数据行共用相同列轨道与单元格内边距，使复选框及各列严格对齐。
4. 运行统计改为“耗时主线 + 紧凑用量”的两层结构：突出点击到结果、模型活跃与排队，其余调用和 Token 指标集中展示，不产生残缺网格。

## 设计方向

延续需求显微镜的冷白、海军蓝和青色证据色。统计区采用一条横向执行账单：左侧两个大号耗时，右侧为紧凑指标；节点成本表仍作为折叠明细。唯一强调元素是“点击到结果”的青色左轨，避免卡片矩阵和大面积灰色占位。

## 验证

- 组件测试覆盖旧任务全部需求渲染、校验明细折叠语义和统计指标。
- 实际 Electron 覆盖三个结果视图、旧任务全部需求、表头与首行对齐、统计区宽屏及 1100px 视口。
- 执行 typecheck、测试、构建、UI 契约和 premium strict audit。
