# 精简 Agent 检查清单

日期：2026-09-15。实施前方案，依据用户确认的“保留必要语义、合并重复来源”设计。当前仅形成方案。

## 目标与范围

将 `agent-checklist.md` 调整为便于编码 Agent 查漏的模块清单：正文突出需求，共同来源集中显示，特殊来源随条目显示。实现依据仍是原始 PRD。

本方案覆盖清单导出和配套说明。此前确认的低成本分析流程是另一项行为调整，本方案不以改造调度器作为前置条件。清单排版使用程序完成，新增模型调用数为零；已有完整结果可直接重新导出。

保留现有功能顺序、需求顺序、编号、本期范围及需求文字。不给需求增加验收步骤、实现建议、平台状态或原文摘录，不用模型自动去重、合并或压缩需求。必要的否定、条件、范围限定继续在条目中保留。

## 当前实现

- `electron/export-agent-package.ts` 的 `implementationMarkdown()` 逐需求输出复选框，并为每条引用追加独立的“原文”子列表。
- `electron/export-excel.ts` 的 `sourceLocation()` 输出完整路径、位置和 UTF-16 字符偏移，被 Markdown 导出复用。
- `src/result-presentation.ts` 已有需求文字、来源引用和位置读取函数；原文结构上下文中可包含解析器产生的章节路径。
- 发布前已逐字回读清单、比对需求编号集合并检查文件哈希；保留这些确定性检查。
- 当前 Agent 包版本为 7。README 产品介绍仍有 CSV、Excel 的过期描述，需与实际包结构同步。

## 文件内容

格式示例，名称、条款和章节不是待新增的业务要求：

```markdown
# 活动管理需求检查清单

> 先阅读原始 PRD，再用本清单查漏；完成后勾选。

主 PRD：[活动管理.md](sources/files/活动管理.md)

## F-001 活动管理

默认原文：主 PRD · 3.1 活动管理

- [ ] R-001：支持停用活动；停用后禁止新增关联。
- [ ] R-002：支持导出活动列表。
- [ ] R-003：支持查询历史活动。（原文：主 PRD · 附录 A）

## F-002 专家分配

默认原文：主 PRD · 3.2 专家分配

- [ ] R-004：支持批量分配专家。
- [ ] R-005：仅该次有效分配的原分配者可以撤回。
```

“默认原文”适用于未单独标注来源的条目；条目自己的“原文”是完整来源集合，覆盖默认值，不与默认值隐式叠加。特殊来源较多时放在该条目的单行缩进说明中，仍只有一个任务复选框。

## 来源展示规则

### 文件与位置

1. 从实际引用解析来源文件，使用原有逻辑路径和冻结文件清单核实，不从需求文字或功能名称推断路径。
2. 文首集中列出引用文件链接。唯一主 PRD 使用“主 PRD”；多文件使用“原文 1”等无歧义标签，并显示实际文件名或相对路径。未被需求引用的补充资料仍在 `sources/files/` 中，不额外复制一份目录导航。
3. 阅读位置优先使用解析器明确记录的完整章节路径；缺少章节时使用原生页码、表格位置、行号或已有 `location`。不用可能来自正文摘要的 `label` 冒充章节。
4. 不同文件、不同父章节下的同名标题不能合并；章节身份还需利用已有位置或标题来源标识消除同文件重复标题歧义。无法确认同一章节时保留原始位置。
5. 阅读位置不默认显示内部来源 ID、文件版本和单元内字符偏移；如果字符位置是唯一可定位信息，则保留它，不删除最后一个定位依据。
6. 平台内部 `sourceRefs`、字符选区与冻结原文原样保留。导出的章节级位置是阅读导航，不声称它保存了每个字符的精确证据映射。
7. 文件链接指向包内真实文件；没有真实锚点就不制造章节跳转链接。文件名含空格、括号、井号等字符时正确编码链接，中文标题和需求中的 Markdown 符号安全显示。

### 模块内合并

1. 为每条需求形成去重后的完整阅读位置集合，位置排序保持确定性。
2. 按整个集合判等，至少两条需求使用相同集合时，才有提到模块下的收益。
3. 选择重复次数最多的集合为模块默认来源；并列时选择需求顺序中最先出现的集合。既有需求不为排版重新排序。
4. 与默认集合相同的条目省略来源；不同的条目注明自己的完整集合。
5. 没有重复集合时不生成模块默认来源，每条需求保留简短位置。单需求模块也沿用此规则。
6. 多来源条目不能只保留第一个位置，不能把模块内全部来源取并集后假定每个条目都适用。

这套规则只合并来源的展示，不合并需求。原文位置高度分散的清单可以保持较长，不设置压缩率或固定字数门槛。

## 公共约束与使用说明

- 已有 `kind=constraint` 的模块保持一次输出，并用现有 `appliesToFeatureIds` 显示本次导出范围内的适用模块编号；不复制其需求到每个模块。
- 普通模块中的相似需求保持原样，导出器不判断它们是否语义重复，也不推断新的约束适用关系。
- 每个本期需求恰好一个 `- [ ]`，不增加模块复选框、完成率、待办建议或可变状态汇总。
- 包内 README 保留简短阅读和使用方法，说明“基于原始 PRD 实现，用清单逐项核对”。清单头只保留一句提醒，不重复长篇使用说明。
- 包结构仍为 `README.md`、`agent-checklist.md`、`manifest.json` 和 `sources/files/`。
- 导出生成新包，不覆盖用户已经勾选的工作副本；manifest 记录初始导出内容的完整性，用户勾选后工作副本自然会改变。

## 改动落点与顺序

1. 在 `electron/export-agent-package.ts` 现有导出器中实现紧凑来源归并与 Markdown 渲染，复用已有类型和来源解析能力。新逻辑仅服务该导出器，暂不新建通用渲染框架。
2. 如果读取结构化章节路径需要抽取公共函数，在 `src/result-presentation.ts` 复用现有上下文清理逻辑；不改变其他界面的现有来源显示行为。Markdown 格式不再依赖 Excel 的完整来源字符串进行拆分。
3. 更新包内 README 模板。Agent 包格式版本由 7 升至 8，使相同分析结果的新格式包获得不同身份；更新 manifest 类型和测试。分析输入、节点契约不变，不升级 Pipeline，也不要求重新分析原文。
4. 在 `tests/agent-package.spec.ts` 扩充来源归并与实际导出回读用例，继续使用已有测试工作目录和清理机制。
5. 更新当前 `README.md`、`AGENTS.md`、`DESIGN.md`、`UX-CONTRACT.md` 中相关交付说明及示例，并清除 README 过期 CSV/Excel 描述。历史 `docs/spec/` 是前置快照，不倒改其历史内容。

本方案单独归档的理由：这是在既有最小包方案之后确认的展示契约变化，应保留前后决策，不覆盖原方案。

## 验收标准

| 场景 | 预期 |
| --- | --- |
| 多条需求来自同一章节 | 共同来源仅在模块下出现一次 |
| 模块内一条来自附录 | 该条显式显示附录，其他条目使用默认来源 |
| 条目同时引用正文和附录 | 两个位置都保留，不隐式继承错误来源 |
| 来源完全分散或仅一条需求 | 每项保留自己的位置，无虚假的共同来源 |
| 同名章节、同名文件 | 文件和章节身份不混淆，无法合并时保留位置 |
| 没有章节的 PDF、表格、文本 | 保留实际页码、表格或行号等已有定位信息 |
| 公共约束、部分范围排除 | 需求不重复，适用模块仅包含导出范围内目标 |
| 否定、数量、条件、多行和 Markdown 特殊符号 | 业务文本保留，每项仅一个可勾选框，链接可解析 |
| 需求编号、顺序与归属 | 与当前导出范围的数据一致，不因排版改变 |
| 旧包或已勾选工作副本存在 | 新包另行生成，旧文件不被覆盖 |
| 文件完整性 | 回读内容、需求编号集合、原始文件及 manifest 哈希匹配 |
| 成本 | 仅导出已有结果，新增模型调用为零 |

实施后运行导出相关测试、类型检查与构建；通过实际 Electron 导出入口重导出一份已有完整任务并打开 Markdown，核对默认来源、例外来源、链接和原始文件，不触发真实模型重新分析。按风险补充全量回归一次，不增加语义审查调用。

## 交付界限

完成标准是“同一份需求内容更易阅读、来源仍可定位、导出完整性不退化”。不将排版去重等同于语义去重，不用新模型审查证明清单零遗漏。
