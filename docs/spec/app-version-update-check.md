# 应用版本展示与更新检查

## 目标

- 在所有页面的顶部栏持续展示当前安装版本。
- 在 Runtime 配置页提供手动更新检查，明确区分检查中、已是最新、发现新版本和检查失败。
- 发现新版本时只打开本项目的 GitHub Releases 页面，由用户自行下载并安装。

## 当前事实

- 应用版本由 Electron `app.getVersion()` 读取，打包后与 `package.json` 版本一致。
- 正式版本由 `.github/workflows/release.yml` 发布到 GitHub Release，稳定版本标签格式为 `v<semver>`。
- 仓库为公开仓库，可通过 GitHub `releases/latest` 接口匿名读取最新正式版本。

## 方案

1. 新增独立的更新查询模块，负责版本规范化、SemVer 比较、GitHub 返回值校验和超时控制。
2. Electron 主进程新增三个窄 IPC：读取当前版本、检查最新版本、打开固定的 Releases 页面。
3. preload 仅暴露上述动作，不向渲染进程开放任意网址或底层网络能力。
4. 顶部栏展示当前版本；Runtime 配置页新增“应用版本”卡片，更新检查由用户主动触发。
5. 网络失败不覆盖已知的当前版本；界面保留重试入口，不把失败误报为“已是最新”。

## 边界

- 本次不做静默检查、自动下载、自动安装、增量更新或预发布版本订阅。
- 只比较稳定的语义版本；远端返回无效标签时明确报错。
- Release 跳转目标固定为本项目官方 Releases 地址，渲染进程不能传入外部 URL。

## 验证

- 单元测试覆盖版本比较、最新版本解析、HTTP 失败和无效响应。
- 类型检查、完整测试、生产构建及 UI 契约检查全部通过。
- 在真实 Electron 实例中验证当前版本、检查中、最新版/有新版、失败与跳转入口的呈现。
