# 需求细化平台

需求细化平台是一款面向中大型需求的桌面工具，用来在开发开始前，把一份定版 PRD 拆成可以逐项实施、逐项核对的功能与需求清单。

中大型 PRD 往往包含大量功能、规则、字段、例外和跨模块约束。直接把整份 PRD 交给 AI 编码，容易在长文本中漏掉功能或细节，而且完成后也很难判断究竟覆盖了多少。这个工具先把 PRD 中的要求逐项拆开，并保留每项需求对应的原文依据。后续无论由 AI 还是人工开发，都可以按清单实施、按清单验收，减少遗漏。

## 它能做什么

- 读取 HTML、DOC、DOCX、PDF、Markdown、TXT 等格式的定版 PRD。
- 将 PRD 整理为业务功能、需求明细、跨功能约束和待处理事项。
- 为每项结果保留原文内容及位置，方便回查为什么有这条需求。
- 区分已明确的需求、需要业务确认的问题和平台需要继续整理的问题。
- 支持按实际开发范围标记“本期做”或“本期不做”。
- 生成编码 Agent 可逐项执行的 CSV 清单，以及 Markdown、JSON 和 Excel 交付包。

它不是一键生成代码的工具，也不会替代产品、研发或测试做最终业务判断。它解决的是编码之前的需求整理问题：先把要做什么拆清楚，再逐项开发和验收。

## 适合什么时候用

适合这些场景：

- PRD 篇幅较长，包含多个功能、角色、状态或业务流程。
- 需求分散在正文、表格、附录和补充资料中。
- 计划让 AI 参与开发，但担心一次性处理整份 PRD 时漏项。
- 需要把需求交给多人或多个 Agent 分工，并统一核对完成范围。
- 上线前需要按原文逐项检查功能和细节是否已经落实。

对于只有几条明确改动的小需求，直接整理任务清单通常更高效，不一定需要使用本工具。

## 怎么用

1. 在“Runtime 配置”中配置可用的 AI Runtime，并完成连接检查。
2. 新建任务，选择一份定版主 PRD。
3. 按需添加补充文档、历史资料或背景说明。
4. 点击“开始分析”，等待平台读取资料并拆分需求。
5. 在任务结果中查看“功能与需求”和“待处理事项”，结合原文依据进行确认。
6. 按本期范围排除暂不实施的内容；如有拆分不合适或业务口径需要补充，可在结果页统一提交调整说明。
7. 确认后生成交付包，将需求清单交给开发 Agent、研发和测试逐项实施与验收。

建议把交付包作为开发和验收的共同清单：每完成一项需求，就核对对应行为、条件、限制、验收条件和原文依据，而不是只检查最终页面看起来是否完成。

## 交付结果

平台会基于同一份需求结果生成：

- `implementation.csv`：编码 Agent 的逐需求实施与验收清单。
- `requirements.json`：适合开发 Agent 或其他程序读取的结构化需求。
- Markdown：适合研发、产品和测试阅读的按功能需求说明。
- Excel：包含功能清单、需求明细、待处理事项、检查记录和原文追踪。
- 来源索引：用于从拆分结果回查原始 PRD。

把完整交付目录放入目标代码仓库，并让编码 Agent 从交付包内的 `README.md` 开始。Agent 会按 `implementation.csv` 逐项记录实现状态、代码依据、验收状态和实跑证据；需求全文、跨功能关系、待处理事项及原始依据仍从同目录的 JSON、Markdown 和来源文件读取。

“可以交付”表示当前范围已经形成可实施的需求清单，不表示代码已经完成，也不代表 AI 可以证明自然语言意义上的 100% 零遗漏。仍未确认的事项会明确保留在结果中，供后续处理。

## 本地运行

当前仓库暂未在新 GitHub 仓库发布安装包，可以从源码运行：

```powershell
npm install
npm start
```

Windows 本地打包：

```powershell
npm run dist:win
```

macOS 本地打包：

```bash
npm run dist:mac
```

开发实现、目录职责、关键约束和验证命令见 [AGENTS.md](AGENTS.md)。历史方案与验收证据分别保存在 `docs/spec/` 和 `docs/acceptance/`。
